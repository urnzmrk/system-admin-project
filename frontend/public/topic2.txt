# Topic 2 — OPERATING SYSTEM, LINUX PLATFORM & SYSTEM FOUNDATIONS

## 1. Introduction to Operating Systems
An operating system (OS) is the system software that manages computer hardware, software resources, and the common services required by application programs. It sits between the user or application and the physical machine. Instead of every program controlling the processor, memory, disks, keyboard, network adapter, and other devices directly, the operating system coordinates those resources and provides controlled ways for programs to use them.
This idea is the foundation of system administration. A system administrator is not only managing applications; the administrator is managing the operating environment that schedules work, controls access, stores files, communicates across networks, and runs services. Understanding the operating system therefore makes later topics such as permissions, networking, servers, and security easier to understand.
## 2. What is Linux?
Linux is a family of free and open-source Unix-like operating systems built around the Linux kernel. In ordinary conversation, the word "Linux" is often used to describe a complete operating system such as Ubuntu, Fedora, Debian, or another distribution. Technically, however, Linux is the kernel at the center of those systems.
A complete Linux system normally combines the kernel with libraries, utilities, package-management tools, shells, system services, and—on desktop systems—a graphical environment. This combination is packaged as a Linux distribution or "distro." The same Linux kernel can therefore appear in many different systems that look and behave differently at the user level.
## 3. What is the Linux Kernel?
The Linux kernel is a free and open-source, Unix-like, monolithic and modular, multitasking operating-system kernel. It was created by Linus Torvalds in 1991 for an i386-based personal computer and later became the kernel used together with GNU utilities in many complete operating systems.
The kernel is the part that stays closest to the hardware. It manages processor time, memory, devices, filesystems, networking, and system calls. Applications normally request services from the kernel instead of manipulating hardware directly.

## 4. Kernel, Operating System and Distribution
These three terms are related but not identical. The kernel is the core component that manages hardware and system resources. The operating system is the complete environment that allows users and applications to work. A distribution is a packaged Linux operating system that combines the kernel with selected tools, libraries, applications, configuration defaults, and package repositories.
This distinction explains why Ubuntu, Debian, Fedora, Arch Linux, SUSE, and other systems can all be called Linux while using different package managers, installation methods, desktop environments, and administrative conventions.
## 5. Linux on Desktop, Server and Embedded Systems
Linux can be used in multiple roles. A desktop distribution usually includes a display system and desktop environment such as GNOME or KDE Plasma. A server distribution may omit the graphical interface and focus instead on network services, remote administration, storage, web hosting, databases, or other server workloads.
Linux to embedded devices and Android-based systems. This demonstrates that Linux is not restricted to one type of computer. The same kernel family can be adapted to personal computers, servers, networking devices, mobile systems, and specialized hardware.
## 6. Server vs. Desktop Linux
A desktop system is designed primarily for an interactive user and commonly includes a graphical interface, desktop applications, audio, printing, and other personal-computing features. A server system is optimized around providing services to other computers or users over a network. It may run without a graphical desktop because administrators can manage it through the command line or remote tools.
The difference is therefore not that server Linux uses a completely different operating-system idea. Both share the same Linux foundations; what changes is the package selection, configuration, intended workload, and user interface.
## 7. Why Linux Matters in System Administration
Linux is closely associated with server administration because it provides powerful command-line tools, network services, configurable permissions, package management, automation-friendly interfaces, and a large open-source software ecosystem. Linux as the environment in which many administration concepts are practiced.
Learning Linux administration also builds concepts that are transferable to other systems: account management, permissions, network configuration, service control, software installation, logging, security, and troubleshooting are universal system-administration concerns even when their exact commands differ.
## 8. Core Responsibilities of an Operating System
An operating system coordinates the major resources of a computer so that applications can run without controlling hardware directly. Its responsibilities include process execution, memory use, storage access, device input/output, user access, and communication between programs.
For a system administrator, these responsibilities appear as practical tasks: checking CPU and memory use, managing storage, controlling users, configuring services, and troubleshooting hardware or software failures.
## 9. Hardware, Software, and the Operating-System Boundary
Computer hardware includes the processor, memory, storage devices, network interfaces, and peripherals. Application software depends on the operating system to use those resources safely and consistently.
This separation is important because the OS provides standard interfaces. A program does not need to know the electrical details of a disk controller; it asks the operating system to read or write a file, and the operating system coordinates the operation.
## 10. System Calls and Operating-System Services
A system call is a controlled request from a program to the kernel. Common activities such as opening a file, creating a process, allocating memory, or sending data through a network ultimately depend on kernel services.
This explains why the kernel is central even when users work through graphical applications. The visible application is only the upper layer of a much deeper operating-system stack.
## 11. Multiuser and Multitasking Operation
Linux is designed to support multiple users and multiple processes. Each process executes with an identity and a set of permissions, while the kernel schedules processor time and protects one process from improperly interfering with another.
Multiuser design is especially important on servers, where many users, applications, and network services may share one system at the same time.
## 12. Linux as a Unix-like Platform
Linux is described as Unix-like because it follows many design ideas and interfaces associated with Unix systems. These include a hierarchical filesystem, command-line tools, user and group ownership, process-oriented design, and a strong tradition of small utilities that can be combined.
Being Unix-like does not mean Linux is the original Unix codebase. It means Linux implements a compatible style of operating-system behavior and administration.
## 13. Administrative View of a Linux System
A useful administrative model is to view Linux as layers: hardware at the bottom, the kernel above the hardware, system libraries and services above the kernel, and user applications at the top.
When troubleshooting, administrators often move through these layers. A problem that appears in an application may actually be caused by permissions, a stopped service, a network interface, a full filesystem, or a kernel-visible hardware problem.
## 14. Common Linux Use Cases
Linux can appear as a desktop operating system, a server platform, an embedded system, a mobile-kernel base, or a specialized security distribution. The same core ideas—users, permissions, filesystems, processes, services, networking, and package management—remain important across these roles.
This flexibility is one reason Linux is useful in system-administration education: the same foundational knowledge can be applied to many kinds of systems.
## 15. Key Takeaways
An operating system manages hardware resources and provides services to programs.
Linux is technically the kernel, while a Linux distribution is a complete usable operating system built around that kernel.
The kernel forms the bridge between software and hardware.
Linux can be used for desktop, server, embedded, and mobile-related platforms.
These foundations support every later topic in Linux administration and ethical hacking.
Core Principle: A Linux system is best understood as layers of hardware, kernel, system services, and user applications working together.
