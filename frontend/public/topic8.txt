# Topic 8 — LINUX INSTALLATION, BOOT ARCHITECTURE, BOOT LOADERS & SYSTEM REQUIREMENTS

## 1. Preparing to Install Linux
Installing Linux begins with choosing a distribution that matches the hardware and intended use. The installation media is normally provided as an ISO image that can be written to a USB device, attached to a virtual machine, or otherwise used as bootable installation media.
Installation as a sequence that includes keyboard settings, storage partitioning, timezone selection, user information, and copying system files to disk. These choices determine how the installed system will boot and how users will access it.

## 3. Partitioning and System Storage
Partitioning divides a physical or virtual disk into logical regions that can be used for the operating system, user data, swap, or other purposes. The exact partition layout depends on the distribution and use case.
For beginners, installers often provide automatic partitioning. Administrators may choose manual partitioning when they need specific filesystems, mount points, or storage separation.
## 4. What is a Boot Loader?
A boot loader is software that starts before the main operating system and loads the selected kernel or operating system into memory. On systems with multiple operating systems or multiple kernel versions, the boot loader may present a menu allowing the user to select what to boot.
Introduces GNU GRUB, LILO, BURG, and Syslinux as examples of Linux boot loaders.
## 5. GNU GRUB
GNU GRUB stands for GNU GRand Unified Bootloader and is widely used by Linux distributions. It supports multiboot configurations, multiple hardware architectures, interactive command-line operation, configuration editing, password protection, and network-related boot capabilities.
GRUB 2 replaced the older original GRUB, which became known as GRUB Legacy. Understanding GRUB is important because a boot-loader problem can prevent an otherwise healthy Linux installation from starting.
## 6. LILO, BURG and Syslinux
LILO, the Linux Loader, was historically used by many Linux systems but its development stopped in 2015. It lacks some of the interactive and network-boot capabilities found in GRUB.
BURG was derived from GRUB and explored alternative text and graphical boot-menu designs. Syslinux is a family of lightweight boot loaders useful for booting from media such as CD-ROMs or from networks and supports common filesystems used in boot environments.

Includes example requirements for several distributions such as Arch Linux, Kali Linux, Linux Mint, Ubuntu, Fedora, and SUSE. Requirements vary according to desktop environment, included software, and intended workload.
Requirements should therefore be treated as practical planning guidance rather than a universal Linux specification. A server without a graphical interface may need fewer resources than a full desktop, while development or security-testing systems may benefit from more memory and storage.
## 8. Linux Server Installation in a Virtual Machine
The server lesson uses VirtualBox as an example environment: download a Linux Server ISO, create a virtual machine, attach the ISO, boot the VM, and select the installation language and keyboard layout. Virtualization makes it possible to practice installation and administration without requiring a separate physical computer.
This same approach later becomes useful for ethical-hacking labs, where isolated virtual machines can be used as controlled targets.
## 9. Linux Installation Workflow
A typical Linux installation includes booting installation media, choosing language and keyboard settings, configuring storage, selecting a timezone, creating user information, copying system files, and installing a boot loader.
The exact screens vary by distribution, but the underlying decisions are similar.
## 10. Installation Media and ISO Images
Linux distributions are commonly distributed as ISO images that can be written to optical media, USB drives, or attached to a virtual machine.
For server laboratories, using an ISO inside VirtualBox or another hypervisor allows students to practice installation without changing the host computer.
## 11. Partitioning
Partitioning divides a storage device into logical regions that can hold filesystems or special data such as swap. Installation tools may create partitions automatically or allow manual control.
Administrators should understand that partition choices affect available space, recovery options, and how filesystems are organized.
## 12. User and Timezone Configuration
During installation, Linux normally asks for a primary user and system timezone. The user account becomes the initial identity for administration, while the timezone affects logs, schedules, timestamps, and system services.
Correct time configuration is especially important on servers.
## 13. What is a Boot Loader?
A boot loader is software that loads an operating-system kernel and transfers control to it. It may also present a menu when multiple operating systems or kernel configurations are available.
Boot loaders are therefore part of the transition between firmware startup and the operating system.
## 14. GRUB
GNU GRUB is the most widely used Linux boot loader family. It supports multiple operating systems, multiple kernels, an interactive command line, configuration editing, and network-boot-related features.
GRUB 2 replaced the older GRUB Legacy design in most modern distributions.
## 15. LILO
LILO was an important earlier Linux boot loader. It was simple and stable but lacked the interactive capabilities and flexibility that helped GRUB become more common.
Its development was discontinued, making it primarily a historical part of Linux boot architecture.
## 16. BURG and Syslinux
BURG was based on GRUB and focused on configurable boot menus. Syslinux is a collection of lightweight boot loaders often associated with removable media, network booting, and simple boot environments.
These tools demonstrate that Linux booting can be implemented in different ways depending on the storage and deployment scenario.
## 17. System Requirements
Example memory, storage, and CPU requirements are provided for distributions such as Arch Linux, Kali Linux, Linux Mint, Ubuntu, Fedora, and SUSE.
System requirements should be treated as planning guidance. Desktop environment choice, workload, number of services, and virtualization overhead can increase the real resources needed.
## 18. Server Installation in a Virtual Machine
For an administration laboratory, a server ISO can be attached to a VirtualBox virtual machine, booted, and installed as if it were a separate physical computer.
This provides a safe environment for practicing networking, service configuration, permissions, and security.
## 19. Key Takeaways
Linux installation involves boot media, storage configuration, user creation, and system-file installation.
A boot loader loads the operating-system kernel and can support multiboot configurations.
GRUB is the major boot-loader example in ; LILO, BURG, and Syslinux provide historical or specialized alternatives.
System requirements depend on the distribution and workload.
Virtual machines are useful for safe practice with Linux installation and server administration.
Core Principle: A reliable Linux installation depends on correct storage, user, boot, and platform decisions before normal administration begins.
